# 결정 사항

사이트를 만들기 전에 정한 것들입니다. 바꿀 때는 이 문서를 먼저 고칩니다.

- 작성: 2026-11-05
- 구축 순서는 [PLAN.md](PLAN.md), 작업 규칙은 [CLAUDE.md](../CLAUDE.md)에 있습니다.

## 1. 저장소와 주소

| 저장소 | 주소 | 내용 |
|---|---|---|
| `cherryopener/cherryopener.github.io` | `https://cherryopener.github.io/` | 서재(책)와 사이트 본체 |
| `cherryopener/photos` | `https://cherryopener.github.io/photos/` | 웹용 사진과 앨범 목록(`albums.js`) |

- 저장소 이름이 정확히 `<아이디>.github.io`여야 사이트 주소의 맨 위(`/`)에 연결됩니다.
- 무료 플랜에서는 두 저장소 모두 **Public**이어야 Pages가 켜집니다. 그래서 공개해도 되는 것만 올립니다.
- 두 저장소는 같은 주소(`cherryopener.github.io`) 아래에 있어서, 브라우저는 둘을 같은 사이트로 취급합니다. 그래서 다른 사이트의 파일을 불러올 때 생기는 CORS 제약 없이 블로그에서 `/photos/...` 경로로 사진과 목록을 바로 불러옵니다.
- 블로그 저장소에는 `photos/` 폴더를 만들지 않습니다. `photos` 저장소의 주소와 겹칩니다.

## 2. 사이트 엔진

- 친구의 저장소 [`yhlee52/bookshelf`](https://github.com/yhlee52/bookshelf) 구조를 기반으로 합니다.
  - 빌드 도구 없이 HTML·CSS·JS 파일만으로 동작합니다. `main` 브랜치를 그대로 Pages에 배포합니다.
  - `.nojekyll` 파일로 Jekyll 변환을 끕니다.
  - `data/books.js` 파일 하나가 사이트 전체 목차입니다. 여기서 책과 장을 추가하면 홈, 책장, 검색, 이전/다음 링크가 자동으로 갱신됩니다.
  - 이론서용 부품이 있습니다. 정의·정리·예제 상자, 자동 번호, 접는 증명, 연습문제, 퀴즈, KaTeX 수식, 인터랙티브 실험을 쓸 수 있습니다.
- 그 저장소에는 LICENSE 파일이 없지만, **친구에게 사용 허락을 받았습니다** (2026-11-05). 출처는 README에 밝힙니다.
- 친구의 책 내용(`books/*`)은 가져오지 않았습니다. 엔진, 템플릿, 실험 모음만 씁니다.
- 사용자 사이트(`<아이디>.github.io`)로 올리므로 `404.html`의 `FORCE_BASE`를 `"/"`로 바꿉니다.

## 3. 사진

### 3-1. 무엇을 올리나

- **원본은 git에 올리지 않습니다.** 원본은 외장하드, 사진 클라우드처럼 git 밖에 따로 보관합니다. GitHub은 백업 서비스가 아닙니다.
- **웹용으로 변환한 사진만** `photos` 저장소에 올립니다.
  - 본 사진: 긴 변 2000px, WebP, 장당 약 300~500KB
  - 썸네일: 긴 변 400px, 장당 약 30~60KB
- 사진 안의 메타데이터(EXIF)는 **전부 지웁니다.** GPS 위치는 특히 반드시 지웁니다. 카메라, 렌즈, 필름, 노출 같은 촬영 정보는 보여주고 싶으면 `albums.js`에 글자로 따로 적습니다.

### 3-2. 용량 한도

| 한도 | 무엇을 세나 | 지운 사진도 포함? | 크기 |
|---|---|---|---|
| Pages 사이트 | 지금 공개된 파일 | 아니오. 지우면 바로 줄어듭니다 | 1GB (반드시 지켜야 함) |
| 저장소 | 과거 기록 전체 | 예. 계속 남습니다 | 1GB 권장, 5GB 강력 권장 |
| 파일 1개 | — | — | 50MB부터 경고, 100MB 넘으면 push 거부 |
| 트래픽 | — | — | 월 100GB 정도의 느슨한 제한 |

- 위 수치는 2026-11 기준으로 알고 있는 값입니다. 정확한 최신 값은 GitHub 공식 문서에서 확인합니다.
- git은 지운 파일도 기록에 남깁니다. 그래서 관리할 숫자는 **지금까지 올린 사진의 총합**입니다. 웹용으로 줄이면 1GB에 약 2,000장, 5GB에 약 10,000장이 들어갑니다.
- 이미 올린 사진을 다시 보정해서 올리지 않습니다. 같은 사진이 두 장 분량을 차지합니다.
- `photos` 저장소가 800MB를 넘으면 정리 방법을 정합니다.
  - 기록에서 사진을 완전히 지우려면 `git filter-repo`를 씁니다.
  - 또는 `photos` 저장소만 새로 만들어 기록을 처음부터 다시 시작합니다.
- Git LFS는 쓰지 않습니다. 브랜치 배포 방식에서는 Pages가 LFS 파일을 제대로 보여주지 않고, 사용량 한도도 따로 있습니다.

### 3-3. 내 컴퓨터에 사진을 두지 않으려면

- 사진을 지우고 커밋하면 최신 버전에서도 **삭제**되어 사이트에서 사라집니다.
- 대신 sparse-checkout으로 사진 폴더만 내 컴퓨터에서 뺍니다. 사진은 GitHub에 그대로 있고 내 디스크에만 없으며, 커밋해도 삭제로 잡히지 않습니다.

```bash
# photos 저장소에서. 사진은 img/ 아래에 둡니다 (예: img/2026/jeju/001.webp)
git sparse-checkout set --no-cone '/*' '!/img/'
```

- 처음 받을 때 `git clone --filter=blob:none`을 쓰면 사진 원본도 내려받지 않습니다.

### 3-4. 블로그에서 사진 부르기

- 사진 주소의 앞부분은 `data/site.js`의 `photoBase` 하나로 정합니다. 내 컴퓨터에서 미리 볼 때는 `/photos/`가 없기 때문입니다.
  - 배포된 사이트: `/photos/`
  - 내 컴퓨터(`localhost`): `https://cherryopener.github.io/photos/`
- 쓰지 않는 방법:
  - `raw.githubusercontent.com` 직접 링크: 이미지를 띄우는 용도가 아니라 느리고 요청 수 제한에 걸립니다.
  - git submodule: 사진이 블로그 사이트에 합쳐져서 블로그의 1GB 한도를 같이 씁니다.

## 4. 사이트 이름과 소개

- 이름은 **"따개"를 살린 이름**으로 합니다. 확정 전까지 가제 `지식따개`를 씁니다.
- 소개의 느낌은 **"매일 재미있게 배우는 곳"**입니다. 지금 문구는 "매일 하나씩, 재미있게 따 보는 지식"입니다.
- 저자 표시는 하지 않습니다. `SITE.author`가 비어 있으면 꼬리말과 홈의 "저자의 말"이 숨겨집니다.
- 이름을 바꾸는 방법은 README의 "사이트 이름 바꾸기"에 있습니다.

## 5. 서재에 넣을 분야

| id | 분야 | 예 |
|---|---|---|
| `phys` | 물리학 | 학부·대학원 이론서. 사용자가 물리학과 출신이라 전공 분야가 곧 물리학입니다 |
| `lang` | 외국어 | 독일어, 러시아어 |
| `ai` | AI | 딥러닝, LLM, 논문 해설 |
| `prog` | 프로그래밍 | 언어, 자료구조, 시스템 |
| `music` | 음악 | 작곡, 화성학 |
| `photo` | 사진 | 필름, 디지털 |
| `misc` | 기타 | 위에 없는 것 |

- 친구의 실험 모음은 분야를 다시 붙였습니다: 딥러닝·시계열 실험은 `ai`, 물리·수학 실험은 `phys`.
- 책마다 난이도(`level`, 1~5)를 정합니다.
- 이 난이도가 그 책을 쓸 모델과 effort를 정합니다. 규칙은 [CLAUDE.md](../CLAUDE.md) 4절에 있습니다.
